# UI consistency audit — Creator vs. Joiner flows

Prompted by the observation that the UI "seems inconsistent" across the
app. Started as an audit + plan (Findings/Plan sections below); the
Implementation section records what actually shipped once the user asked
to act on it. Findings are also recorded in
[architecture/ui-design-system.md](../architecture/ui-design-system.md),
which is the doc to keep current going forward — this file stays a
point-in-time writeup of what was found, planned, and done.

## Method
Read the shared UI kit (`src/ui/components.tsx`) and the two flows that
implement the same bill-splitting steps twice — the Creator's
`SessionHomePage.tsx`/`BillEditorPage.tsx` (+ `StepIndicator.tsx`,
`ItemsInput.tsx`, `ItemAssignment.tsx`, `BillSummary.tsx`) and the Joiner's
`JoinPage.tsx`/`JoinerBillEditorPage.tsx` — then grepped for repeated raw
Tailwind strings across `src/` to quantify how much markup is copy-pasted
rather than shared.

## Findings

1. **Step indicator, duplicated with drift.** `StepIndicator.tsx` reads
   `step`/`goToStep` straight from `billStore`, so `JoinerBillEditorPage.tsx`
   (whose step comes from the URL, not `billStore`) can't reuse it and
   reimplements the same 3-circle markup inline. The copies have already
   diverged: the creator's has a progress line under the circles, the
   joiner's doesn't.
2. **Back navigation: two competing styles for one action.**
   `BillEditorPage.tsx`/`JoinerBillEditorPage.tsx` render "← Back to
   Session" as a filled `variant="primary"` `Button` — visually a call to
   action. Every other back/away link in the app (`JoinPage.tsx`'s
   not-found/error/disapproved screens, `JoinerBillEditorPage.tsx`'s own
   identity-error/bill-not-found screens, `SessionHomePage.tsx`'s
   session-not-found screen — 18 sites total) uses a plain underlined text
   `<Link>`. Same intent, two unrelated visual treatments, chosen ad hoc
   per call site.
3. **Settings gear icon: 20-line SVG pasted 3 times.** Identical inline
   SVG + button wrapper in `App.tsx`, `BillEditorPage.tsx`, and
   `SessionHomePage.tsx`, no shared `IconButton` component.
4. **Headings: one literal className, pasted 19 times.**
   `"text-xl font-semibold mb-4 text-zinc-800 dark:text-white
   transition-colors"` (or a margin variant) is copy-pasted verbatim across
   19 h2/h3 elements in both flows. Consistent today by luck, not by
   contract.
5. **Status/empty screens skip `Card`.** `JoinPage.tsx`'s not-found /
   pending / disapproved / error screens are raw centered `<div>`s, the
   only "informational box" surfaces in the app that don't use `Card`.
6. **One hand-rolled `<input>`.** `JoinPage.tsx`'s "Your name" field
   doesn't use the kit's `Input` component, unlike every comparable field
   elsewhere.

None of these are functional bugs — every flow works. The cost is
*drift and duplicated effort*: each new page currently re-derives the same
5-6 shapes from scratch in Tailwind, which is exactly how findings #1 and
#2 happened.

## Plan
Extend `src/ui/` with the missing shapes, then migrate call sites
incrementally, one small commit per shape (per root `CLAUDE.md`'s
"commit in small, independently verifiable phases"):

- [x] `BackLink` — underlined text link (the existing style), replaces
      the 2 primary-`Button` back-navigation call sites in
      `BillEditorPage.tsx`/`JoinerBillEditorPage.tsx` and standardizes
      every existing `Link` call site (JoinPage, SessionHomePage,
      SessionSettlementPage, ActivityLogPage, LiveSessionPanel — turned
      out to be 11 sites, not the estimated 18) onto one component.
- [x] `IconButton` — generic `icon`-prop wrapper around the shared
      button chrome duplicated for the settings gear; applied to the 2
      true duplicate button sites (`BillEditorPage.tsx`,
      `SessionHomePage.tsx`). `App.tsx`'s copy is structurally different
      (icon data inside `Sidebar`, not a standalone button) — left as-is,
      noted as optional follow-up.
- [x] `Heading` — h2-by-default, `margin: 'none'|'sm'|'md'` prop,
      replaces all 19 sites.
- [x] `StepBar` — presentational, `step`/`steps`/`onStepClick`, no store
      coupling. `StepIndicator.tsx` is now a thin `billStore`-bound
      wrapper around it; `JoinerBillEditorPage.tsx` wraps it off its
      URL-derived step. Fixed the progress-line drift as a side effect.
- [x] `JoinPage.tsx`'s raw `<input>` migrated onto `Input` (its
      not-found/pending/disapproved/error screens were left as plain
      centered `<div>`s rather than forced into `Card` — see
      Implementation below for why).

Each item landed as its own commit — presentational-only, no behavior
change.

## Implementation (2026-09-01, same day as the audit)
The user asked to act on the audit plus three additional asks that
surfaced in the same conversation: `Input` needed real accessibility
markup and every hand-rolled `<input>` in the app should route through
it; toasts were too small; delete actions styled as text links should be
red `Button`s, and anything opening a modal (not real navigation) should
be a `Button` too. Shipped as 5 further commits beyond the plan above:

- **Kit split**: `src/ui/components.tsx` (a single ~700-line file) split
  into one file per component, `components.tsx` kept as a pure barrel
  re-export — zero import-path changes across the ~40 consuming files.
- **`Input` accessibility**: `aria-invalid`/`aria-describedby` wired to
  the error message (stable id via `useId()`), plus a new `compact`
  variant for cramped contexts.
- **Toast sizing**: `src/ui/Toast.tsx` — `max-w-sm`→`max-w-md`,
  `text-sm`→`text-base`, more padding, a bigger dismiss icon.
- **Link-styled actions → real Buttons**: beyond the originally-known
  "Paid by"/"Delete" on `SessionHomePage.tsx`, the same audit pass (done
  via a fresh grep, not assumed) found three more: `JoinerBillList.tsx`'s
  duplicate delete-bill link, `ClaimQuantityModal.tsx`'s "Remove my
  claim", and `ItemAssignment.tsx`'s "Split Type" (opens a drawer, styled
  as a link). All five fixed the same way: `variant="danger"` for
  destructive, `variant="secondary"` for modal/drawer triggers.
- **Full `<input>` migration** (~17 sites, not just `JoinPage.tsx`'s):
  split into a mechanical batch (no existing validation UI — JoinPage,
  Settings, GoLiveSection, PeopleListShared, EditPersonModal,
  OnboardingModal, PersonSelection, ItemsInput, EditItemModal,
  EditLiveItemModal) and a harder batch rewiring existing hand-rolled
  validation through `Input`'s new `error` slot (UpiNudge, joiner
  AddItemForm, AddPaymentModal). Judgment calls made along the way:
  - `PeopleListShared.tsx`/`PersonSelection.tsx` previously joined their
    input and Add button into a seamed pill (`rounded-l`/`rounded-r-none`)
    — un-seamed to match the rest of the app's "Add X" forms (independent
    rounded elements in a `gap-2` row, e.g. `AddItemForm.tsx`), rather
    than fighting `Input`'s own border-radius to preserve a one-off
    minority pattern.
  - `AddItemForm.tsx`'s single "Enter a name and price" message (not
    per-field) is shown on both the name and price `Input`s' `error`
    props, rather than inventing per-field validation that doesn't exist.
  - `AddPaymentModal.tsx`'s payer-equals-payee message stays a standalone
    paragraph — `SearchSelect` has no `error` slot, and adding one was
    judged out of scope for this pass.
  - `EditPersonModal.tsx`'s previously-silent empty-name no-op now shows
    "Name is required" — the one place new (trivial) validation copy was
    added, since the existing submit gate was already a simple truthy
    check.
  - `FractionalSplitInput.tsx`'s per-person share stepper uses the new
    `compact` variant rather than staying raw.
  - `EditableTitle.tsx`'s dashed-underline inline-edit title field was
    deliberately **not** migrated — a genuinely different widget (inline
    click-to-edit, not a boxed form field), not an oversight.
  - `JoinPage.tsx`'s not-found/pending/disapproved/error screens were
    **not** swapped onto `Card` as the original plan proposed — on review
    that felt like scope creep beyond what was actually asked (link
    style, buttons, input markup); left as a smaller, separately-doable
    follow-up if wanted.

Verification per phase: `npm run typecheck`, `npm run lint`, `npm test`
(306 tests) all green throughout; `npm run build` succeeded after the
full sequence.

## Non-goals for this pass
Visual redesign (new color palette, spacing scale, typography) stayed out
of scope — this was about eliminating *duplicated* markup and mismatched
affordances (link vs. button) for shapes that already have a de facto
consistent look, not changing what that look is.
