## Not in scope / future work

- **Event-based data-sync / event sourcing.** Motivated by an observed bug:
  deleting an item on a bad network connection can cause it to reappear,
  because today's sync (`pushBillFieldsLive`/`mergeLiveSnapshot` in
  `sessionStore.ts`) does direct field overwrites rather than replaying an
  ordered event log, so a stale concurrent snapshot can resurrect a delete.
  A full client+server event-sourced sync system would fix this class of bug
  but is a substantial architectural change (ordering/idempotency guarantees,
  a rewrite of `sessionStore`'s merge logic) — not implemented in this batch.
  Needs its own design doc before scoping into phases (likely a
  `planv4.md`-style doc given its size).

## Decisions log

- Phase 1/2 step-renumbering: wizard steps just shift down by one (old
  2/3/4 -> new 1/2/3); no other step-numbering scheme was considered since
  the route shape (`/step/:n`) stays a plain integer either way.
- Phase 1/2 e2e updates: while fixing e2e specs broken by the step
  renumbering, found `OnboardingModal` (commit `ba8434c`) blocks the first
  interaction on every fresh Playwright browser context (no `storageState`
  reuse), so effectively every "add a person"/"Add Bill" click in every spec
  timed out. Added `e2e/.setup/onboarding-completed.json` +
  `playwright.config.ts`'s `use.storageState` to pre-seed
  `completedOnboarding` and unblock e2e verification — this is test
  infrastructure, not one of the 19 phases, but was necessary to run any e2e
  spec at all.

## Known pre-existing issues (found during verification, out of scope)

A full `npx playwright test` run (55 passed / 5 failed) found 5 pre-existing
failures, none in files this batch's phases touch — not fixed here to avoid
scope creep:

- `join.spec.ts`, `creator-claims-own-identity.spec.ts`,
  `joiner-cannot-claim-creator-identity.spec.ts`,
  `joiner-cannot-reclaim-active-identity.spec.ts`: all four do
  `page.locator('select')...selectOption(...)` against `JoinPage.tsx`'s or
  `GoLiveSection.tsx`'s identity picker, which is now a `SearchSelect` (a
  custom combobox, no native `<select>`). Looks like a leftover from before
  `SearchSelect` replaced a native `<select>` there (see commit `ba8434c`,
  "identity preselect"). All four need rewriting to drive the combobox's
  button + search input instead.
- `sessions-list.spec.ts` ("create and delete a session"): `getByText('Untitled Session')`
  is a strict-mode violation — `SessionsListPage.tsx`'s "Continue current
  session: <span>...</span>" banner and the session's own list-entry link
  both match. Needs a more specific locator (e.g. scope to the list, like
  `bill-editor-flow.spec.ts` already does for its own bill-list assertion).
