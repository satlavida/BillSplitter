## Not in scope / future work

- **Event-based data-sync / event sourcing.** Motivated by an observed bug:
  deleting an item on a bad network connection can cause it to reappear,
  because today's sync (`pushBillFieldsLive`/`mergeLiveSnapshot` in
  `sessionStore.ts`) does direct field overwrites rather than replaying an
  ordered event log, so a stale concurrent snapshot can resurrect a delete.
  A full client+server event-sourced sync system would fix this class of bug
  but is a substantial architectural change (ordering/idempotency guarantees,
  a rewrite of `sessionStore`'s merge logic) — not implemented in this batch.
  Needs its own design doc before scoping into phases (likely a
  `planv4.md`-style doc given its size).
