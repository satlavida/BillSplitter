- [x] **Found and fixed a second real bug while wiring this up**: `middleware.Logging`'s `statusWriter` wraps `http.ResponseWriter` to capture the status code but never implemented `http.Flusher`. Invisible in all prior Go tests because they build the router directly (`New(...).Router()`) without the `Logging` wrapper, and invisible in the first round of Playwright coverage because nothing yet opened a live SSE connection from the browser. Only surfaced once a real two-tab Playwright test subscribed to `/events` against the real `go run ./cmd/server` binary. Fixed by adding a `Flush()` method to `statusWriter` that forwards to the underlying writer's `Flusher`; regression-guarded by `middleware/logging_test.go`'s `TestLoggingPreservesFlusher`.
- [x] **Entity-id-based merge**: `sessionStore.ts` gained `mergeLiveSnapshot(sessionId, liveSession)`, upserting `people`/`bills`/`items` by id (new entities added, existing ones updated in place) rather than replacing arrays wholesale — local-only fields the server doesn't know about (`receiptImage`, `splitStateVersion`) and local people not yet echoed back by the server both survive a merge. 2 new unit tests in `sessionStore.test.ts`.

## Pending — remaining Phase 3 DEV work
Everything below is explicitly deferred, not silently skipped. Roughly in the order it'd make sense to pick back up:

- [ ] **Sync edits to already-pushed bills/items, not just creation.** Only the *first* push of a new bill/item reaches the server; subsequent local edits (price, tax, title, item split/assignment changes) stay local-only, so a live session's server-side settlement can drift from what the creator sees locally. Would need either a diff-and-PATCH endpoint or periodic full-bill resync.
- [ ] **`joinerId` persistence.** A joiner who refreshes `/join/:code` currently loses their place and has to rejoin from scratch. Plan: store the returned `joiner.id` in that browser's localStorage (not `sessionStore` — joiners don't get their own persisted session) and skip straight to the pending/admitted view on reload if present.
- [ ] **Receipt image sync during live sessions.** `POST /api/sessions/{code}/bills/{billId}/images` and `GET /api/images/{refKey}` exist server-side and are covered by nothing on the frontend yet — `ScanReceiptButton.tsx`/`ReceiptImagePreview` only know about the local IndexedDB copy.
- [ ] **Settle flow in the UI.** `POST /api/sessions/{code}/settle` (creator-only, starts the 48h purge clock) has no button/confirmation anywhere in the app.
